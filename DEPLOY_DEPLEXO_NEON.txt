OSV BLUE COMMAND V20 — DB POOL GUARD + PREMIUM CACHE FIX

WHAT CHANGED
- Every PostgreSQL connection opened during an HTTP request is tracked.
- Normal endpoint cleanup remains unchanged; request-finally cleanup now returns any forgotten connection to the pool even if an exception occurs.
- PGConn.close() is idempotent, so normal cleanup and the safety cleanup can both run without double-returning a connection.
- Static asset query versions changed to force browsers to load the current V20 CSS/JS after deployment.
- Existing app features, routes, schema migration, and Neon database connection settings are preserved.

DEPLOY TO DEPLEXO
1. Make a backup/export of the current Neon database before deploying any server change.
2. Extract the ZIP. Put the CONTENTS of the ZIP at the ROOT of the existing GitHub repository used by Deplexo (main.py, requirements.txt, static/ etc.). Do not nest them inside another folder.
3. Build command: pip install -r requirements.txt
4. Start command: uvicorn main:app --host 0.0.0.0 --port $PORT
5. Keep the existing Neon database. In Deplexo Environment Variables verify DATABASE_URL is the complete Neon PostgreSQL connection string, not an API token. Use the pooled connection string provided by Neon. NEON_DATABASE_URL is also accepted if DATABASE_URL is not set.
6. Preserve APP_SECRET to keep existing signed sessions valid. Do not commit DATABASE_URL, APP_SECRET, or OWNER_PASSWORD to GitHub.
7. Wait for a successful deployment, then open /api/health. It should return database=postgresql.
8. Test owner login, registration with a temporary nickname, user list, and deletion of only that test account. Then check login again and confirm the original users/questions/attempts remain.

IF PoolTimeout STILL APPEARS
- Open Neon and confirm the database is active and the pooled connection string belongs to this project.
- Check Neon connection/compute status and whether another deployment or application is consuming all available database connections.
- Review new logs from the V20 deployment, not logs from an older running revision. Do not switch to SQLite as a workaround; that can make the site appear empty and split users from the existing Neon data.

VPN NOTE
If the entire Deplexo URL fails to open without VPN, that is a hosting/DNS/network route issue; Python/CSS changes cannot force the host to be reachable. If the page opens but API requests fail, use browser developer tools Network to see which request fails.
